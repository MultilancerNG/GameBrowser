# GameBrowser companion synchronizer

In the installed GameBrowser live workspace, the trusted Node observer is the single action controller. The companion extension displays assigned roles and provides an explicit Manual control; worker-mode generation grants no website injection permissions and never replays actions. Clicking a follower or changing its active tab keeps its assignment. Closing and reconnecting a browser retains the saved group and explicit pause, with no action backlog.

The legacy standalone extension controller mirrors approved nonfinancial clicks, search text, and document scrolling between isolated profiles through the authenticated loopback relay. The generated per-profile `config.json` is written only into that profile's extension directory at launch. The distributable contains `config.example.json`, never a working token.

Chrome uses `manifest.json`. `manifest.firefox.json` provides a Firefox event-page variant; the managed patched Firefox engine can instead inject the same `content.js` through the local browser bridge. No password, cookie, webRequest, or native-messaging permission is requested. The profile generator restricts manifest permissions and content-script matches to its approved website hosts. Runtime policy further compares the exact origin, including ports. HTTP is permitted only for explicitly approved loopback fixtures; remote sites require HTTPS.

The relay receives `HELLO` authentication before any configuration or action. Production relay endpoints use the current authenticated loopback port at `/workspace/relay`; restart reloads the private per-profile configuration rather than hard-coding port 8080. A 20-second application heartbeat sustains Chrome MV3 WebSocket activity. Disconnects immediately pause capture/replay and reconnect with no event backlog. The server supplies role configuration on reconnect. Only the current active profile tab may capture or receive actions.

With the legacy extension controller, the companion switches to manual mode for authentication pages, password/OTP/CAPTCHA inputs, payment and wager controls, ambiguous selectors, URL/target mismatches, and rejected events. Controls use stable attributes and a unique structural fallback. Before replay, the follower checks the exact approved origin, sanitized pathname, generation, sequence, visibility, unique selector, and target fingerprint. Search text uses native input value setters plus input/change events.

Legacy extension DOM replay produces `isTrusted=false` events. It does not reproduce browser-trusted input or guarantee acceptance by any website. Delay modes pace approved actions; they do not bypass site detection or verification. Each account's credentials, verification, deposits, withdrawals, and wagers remain independent manual actions.

Workspace worker policy enforces approved origins, Fast/Paced FIFO scheduling, and independent manual control for authentication, challenges, payment and wager controls. A policy pause retains the desired group and requires explicit attention. Profile cookies, storage, query identity and fingerprints are not copied.

## Legacy bridge contract

The Firefox bridge wraps `content.js` in a private function scope containing the lexical adapter `__stakemodePrivateSend(message)`. The adapter calls a sealed randomly named browser binding with a private nonce, checked by the server on every packet. No `window.__stakemodeSend` function is exposed. The script installs `__stakemodeConfigure(config)`, `__stakemodeReceive(packet)`, and `__stakemodeDispose()` functions. Config is `{ role: 'admin' | 'follower' | 'manual', origins: string[], epoch: number, connected: boolean, active: boolean }`. The bridge keeps socket credentials in the orchestration process. Every outgoing packet still requires server-side role, origin, nonce, sequence, and event-policy validation; page-world script execution alone is not an authentication boundary.

Actions are `{ type: 'ACTION', id, seq, epoch, origin, url, action: 'click' | 'input' | 'scroll', selector?, fingerprint?, value?, x?, y? }`. URLs contain only the origin and pathname. ACKs use `{ type: 'ACK', id, epoch, status: 'applied' | 'rejected', reason? }`, echoing the received action's recipient epoch. A stale ACK cannot advance a newly resumed queue. Manual takeover uses `{ type: 'MANUAL_OVERRIDE', enabled: true, reason? }`. PAGE messages contain only `{ type: 'PAGE', origin, url }`. The TypeScript relay validator is `workspace/eventPolicy.ts`.
